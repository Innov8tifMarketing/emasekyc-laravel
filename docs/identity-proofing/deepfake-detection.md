# Deepfake & Injection Attack Detection (OkayLive Plus)

## The Problem: Injection Attacks

In a generic eKYC process (Begin IDV → ID Capture → Selfie → Onboarded), fraudsters can intercept at two points:

1. **Injection attack** — bypassing the physical camera using external devices, device emulators, or virtual cameras
2. **Deepfake** — substituting a real face with face swap software or AI-generated portraits

### Injection Tactics (3 types)
1. **Virtual Camera** — Software emulating webcams (e.g., OBS Studio). Used to stream pre-recorded or AI-generated video as if from a real camera
2. **External Device** — Connected electronics that can be recognized as a photo capture device (USB video capture cards, etc.)
3. **Emulators** — Programs that imitate mobile devices (e.g., LDPlayer, BlueStacks). Run the target app in a simulated environment

### Deepfake Techniques (4 types)
1. **AI Face Swaps** — Imposed fake facial data on genuine media (real person's face replaced with another)
2. **AI Synthetics** — Image completely generated by AI (no real source person)
3. **3D Mesh Faces** — Manipulatable head model via 3D modelling software
4. **Digitally Tampered Images** — Edited media with watermarks, artifacts, UI overlays

## OkayLive Plus: Attack Taxonomy

OkayLive Plus addresses the full spectrum of digital identity attacks:

### Presentation Attacks (handled by OkayLive)
- **Attack content**: Physical content — printed copy, screen replay, mask
- **Attack site**: Sensor (camera)
- **Method**: Present non-live reproduction of a facial image to sensor (facial spoof)

### Injection Attacks — Two Products by Attack Vector

**OkayLive Plus** handles device-level injection attacks:

| Attack Vector | Target Layer | Method |
|---|---|---|
| Virtual Camera | Device HW/SW (silicon, drivers, APIs, OS, apps) | Use virtual camera in place of physical camera |
| External Device | Device HW/SW | Use external device to capture and stream video |

**OkayCam SDK Plus** handles browser-level and network-level attacks:

| Attack Vector | Target Layer | Method |
|---|---|---|
| Web Browser Console | Browser (JavaScript) | Replace JavaScript code to bypass camera capture |
| Browser Plugins | Browser | Apply fraudulent codec/camera via plugin |
| Client-Server Protocols | Network | Man-in-the-middle attack intercepting data in transit |

### Digital Content Types Detected (across both products)
- **Attack content**: 3D rendering, face morphing, face swap, cheap fake, deep fake
- **Digital medium**: Image, recorded video, live video

## How OkayLive Plus Works (2-tier architecture)

### Tier 1: OkayLive Plus SDK (client-side, real-time)
- Detects and prevents **injection attack methods** in real time
- **Injection attack detection** via emulators, devices, and virtual cameras
- **Collates** pertinent process data for further analysis on server

### Tier 2: OkayLive Plus Analysis (server-side)
- Carried out in processing servers implementing various tampering detection methods
- **Deepfake detection** for face swaps, synthetics, 3D models, etc.
- **Analysis of metadata** collated by SDK, including network data
